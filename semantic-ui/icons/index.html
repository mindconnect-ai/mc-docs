Icons

semantic-ui ships a curated icon set (sourced from Lucide, ISC-licensed) as a single SVG sprite at /sui/icons.svg. Icons render identically in the SSR (Handlebars) and SPA (TypeScript) paths, inherit the surrounding text's colour (currentColor) and size (1em), and need no build step on the client.

Two ways to place an icon​

1. The icon shorthand on a component​

Most components take an icon token directly — the common leading-icon case:

UiAction.primary("save", "Save").icon("save");           // 💾 leading icon + label
UiAction.secondary("edit", "Edit").icon("pencil")        // icon-only button;
        .appearance(UiAction.Appearance.ICON);           //   label → accessible name
UiField.text("q", "Search", null).asEditable().icon("search");  // in-field icon
UiLink.of("back", "/x", "Back").icon("back");            // leading icon on a link
UiSectionEntry.of("t", "Settings", body).icon("settings"); // tab-heading icon

The same field exists on UiList.Item and UiTree.Node. In JSON it is just a string:

{ "type": "action", "id": "save", "label": "Save", "icon": "save", "style": "PRIMARY" }

2. The UiIcon node — an icon anywhere​

For free placement (inside a UiStack, as a labelNode, in a table cellTemplate) use the standalone node:

UiIcon.of("status", "success").labelled("All good");     // accessible
{ "type": "icon", "id": "status", "name": "success", "title": "All good",
  "cssClass": "sui-icon--success" }

Because it is a real node with an id, a UiPatch can REPLACE or REMOVE it like any other — e.g. flipping a row's status icon without re-rendering the row.

Tokens: semantic aliases vs raw ids​

A token is either a semantic alias or a raw sprite id:

  • Semantic aliases — add, edit, delete, save, search, close, back, success, warning, error, user, settings, download, external, filter, refresh, … These are library-independent: they map to concrete icons in icons/icons.json. Prefer these — app JSON that uses them survives an icon-library swap unchanged.
  • Raw sprite ids — trash-2, chevron-right, … Pass through verbatim for anything without an alias.

A legacy emoji (or any non-token string) is rendered verbatim, so existing icon: "📁" data keeps working — there is no flag day.

Swapping the icon library​

Icons are deliberately behind a resolver, so the library is swappable without touching a single UiNode.

Point at a different sprite (e.g. one your app hosts):

// SSR
IconRenderer.setSpriteUrl("/assets/my-icons.svg");
// SPA
import { setIconSpriteUrl } from "/sui/renderer.js";
setIconSpriteUrl("/assets/my-icons.svg");

Replace the scheme entirely — inline SVG, an icon font, anything:

import { setIconResolver } from "/sui/renderer.js";
setIconResolver((name, opts) =>
    `<i class="fa fa-${name}"${opts.title ? ` title="${opts.title}"` : ""}></i>`);
IconRenderer.setResolver((name, cssClass, title, id) -> "<i class=\"fa fa-" + name + "\"></i>");

Every renderer routes through the active resolver, so one call re-skins all icons on the page.

Adding or changing icons in the default sprite​

The sprite is a generated, committed artifact — the Maven build only copies it. To change the set, edit icons/icons.json (the token → lucide-id map) and regenerate:

cd semantic-ui/mc-semantic-ui-core
npm run build:icons      # rewrites src/main/resources/icons.svg

Commit the regenerated icons.svg. To move to a different icon library altogether, install that library's static-SVG package, re-point the ids in icons.json, and regenerate — the semantic aliases (and all app JSON) stay the same.

Styling​

.sui-icon is 1em × 1em, fill: none, stroke: currentColor. Colour an icon by setting color on it or an ancestor; the sprite's status helpers (sui-icon--success, --warning, --danger, --muted) are ready-made cssClass values for a UiIcon.

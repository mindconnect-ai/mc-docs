Menu button

UiMenuButton is a button that opens a floating dropdown / context menu of UiMenuItems anchored to itself. Where UiMenu is the persistent sidebar, a menu button is transient: it lives closed, opens on click, and closes on outside-click, Esc, or when an item is chosen.

It is deliberately placeable anywhere a node can go — on its own as a toolbar overflow (a "kebab" ⋮), or dropped into another node as that node's context menu.

UiMenuButton.of("row-menu",
    UiMenuItem.of("edit",   "Rename").icon("edit").onClick(UiTrigger.api("POST", "/rename")),
    UiMenuItem.of("dup",    "Duplicate").icon("copy").onClick(UiTrigger.api("POST", "/dup")),
    UiMenuItem.of("share",  "Share").icon("share").onClick(UiTrigger.toast(UiToast.success("Link copied"))),
    UiMenuItem.divider(),
    UiMenuItem.of("del",    "Delete").icon("delete").danger(true).onClick(UiTrigger.api("DELETE", "/x"))
).align(UiMenuButton.Align.END);

The trigger​

By default the trigger is an icon-only button (a ⋮, the more icon). Give it a label and it becomes a normal labelled dropdown button with a caret:

UiMenuButton.of("acts",
    UiMenuItem.of("exp", "Export CSV").icon("download").onClick(UiTrigger.go("/export")),
    UiMenuItem.of("ref", "Refresh").icon("refresh").onClick(UiTrigger.api("POST", "/refresh"))
).label("Actions");            // → a labelled button instead of a kebab
FieldMeaning
itemsThe UiMenuItems shown in the popover.
iconTrigger glyph token. Defaults to more (a vertical ⋮).
labelOptional trigger text; when set, the trigger is a labelled button.
variantICON or BUTTON. Defaults to BUTTON when a label is set, else ICON.
alignSTART (opens rightwards) or END (right-aligned; the default).

The items​

Items reuse UiMenuItem — the same type the sidebar uses — so you get icon, href/onClick, and badge for free, plus two fields that matter most in a popover:

  • danger — a destructive action (Delete, Remove), rendered in the danger colour.
  • divider() — a non-interactive separator line between groups of items.

A leaf with onClick dispatches through the event bus; one with only an href is a plain link (so it still works with no JS).

Nested submenus​

An item with children becomes a submenu — the very same UiMenuItem.children the sidebar menu uses to nest. Build one with UiMenuItem.group(...):

UiMenuButton.of("acts",
    UiMenuItem.of("exp", "Export CSV").icon("download").onClick(/* … */),
    UiMenuItem.group("move", "Move to",              // ← a submenu
        UiMenuItem.of("inbox",   "Inbox").onClick(/* … */),
        UiMenuItem.of("archive", "Archive").onClick(/* … */),
        UiMenuItem.divider(),
        UiMenuItem.of("trash",   "Trash").danger(true).onClick(/* … */)
    ).icon("share"),
    UiMenuItem.link("set", "Settings", "/settings").icon("settings")
).label("Actions");

The group header shows a trailing ›. On the desktop the submenu flies out to the side on hover / focus; on touch a tap opens it. Nesting is arbitrary — a submenu can hold further groups. The SPA flips a submenu to the other side when it would run past the viewport's right edge.

A per-row context menu​

Because a menu button is just a node, you can attach one to any row by putting it in the row's label. A tree row's labelNode, for example, gives every node its own ⋮ menu:

UiTreeNode.of("f1", "report.pdf").icon("document").labelNode(UiStack.of(
    UiText.of("report.pdf"),
    UiMenuButton.of("f1-menu",
        UiMenuItem.of("f1-ren", "Rename").icon("edit").onClick(/* … */),
        UiMenuItem.divider(),
        UiMenuItem.of("f1-del", "Delete").icon("delete").danger(true).onClick(/* … */)
    )
).direction(UiStack.Direction.HORIZONTAL).gap(8));

How it opens (SSR → SPA)​

The menu button renders as a native <details>, so with no JS at all the summary toggles the popover open and closed.

With the SPA event bus loaded it just works — the bus takes over open/close and, crucially, repositions the popover with position: fixed at open time, so it is never clipped by a scrolling or overflow: hidden ancestor (a tree, a table cell, an overlay app-shell). It flips above the trigger when there's no room below and clamps into the viewport; submenus flip to the other side near the screen edge.

const bus = new SuiEventBus(renderer, root);
renderer.mount(page);   // menu-button popovers just work

See the Navigation tab of the widget showcase for a live kebab + labelled dropdown, and the Tree tab for a per-row context menu.

What about wireMenuButtons?

You don't call it as a normal consumer — the SuiEventBus activates the popovers itself after every render. The function is still exported only for the rare case of enhancing static, server-rendered HTML without a bus; then you'd call wireMenuButtons(root) once after the markup is in the DOM.

semantic-ui

Fast, dynamic server-side UI that also runs as a client app. A small, typed JSON vocabulary for building business-app UIs from the server. The same model renders as static HTML (SSR / no JavaScript) and as a live SPA, and is editable through a built-in visual editor.

semantic-ui lets a Spring Boot backend describe a screen as a tree of typed UiNodes (UiForm, UiTable, UiSection, UiField, …) instead of emitting HTML strings or shipping a SPA framework. A small TypeScript renderer and a matching Handlebars-based server renderer turn that tree into the same markup.

One model, one controller, many renderers — today SSR HTML, a live SPA, and the visual editor; the model itself is just typed JSON, so a Swing, terminal or custom renderer is a matter of writing one.

Try it live

Open the interactive widget showcase ↗ — a fully static page (no backend) that renders every UiNode, each shown next to the JSON the renderer consumes and the equivalent Java builder.

Or design your own screens in the visual editor ↗ — a backend-free app where you build pages from a tree of UiNodes, preview them live, and download the result as a runnable static, Spring Boot, or Node.js project.

Why​

Frontend development has reached a mental load that's wildly out of proportion for most CRUD-shaped business apps: build toolchain, reactivity model, state management, routing, form-state, server-state cache, component library, validation, testing. For an internal admin or backoffice UI that's massive overengineering.

semantic-ui's thesis: the UI of a structured business app is fully describable as a small, typed JSON tree. The server emits the tree, a thin renderer turns it into HTML. Design lives in the renderer, not in 200 controller templates.

Where it fits​

  • Admin / backoffice
  • ERP / CRM / accounting / HR / order entry
  • Workflow / wizard / case-management UIs
  • B2B SaaS dashboards with tabular data
  • Configuration / DevOps surfaces
  • LLM-agent-operable UIs (the tree IS the UI contract)

Where it doesn't​

  • Marketing sites, consumer shop frontends with strong design opinions
  • Real-time editors (IDE, whiteboard, spreadsheet)
  • Games, sub-16ms interactivity

In this section​

  • How it works — the controller → UiNode tree → renderer model, with a full example.
  • Node vocabulary — the 16 UiNode types and how they stay symmetric across Java, Handlebars and TypeScript.
  • Widget showcase (live) — a static, backend-free page demonstrating every UiNode, each shown with its JSON and equivalent Java.
  • Diagram extension — a diagram node that renders a directed graph as an interactive SVG canvas.
  • Build an app (SPA) — a complete app: index.html shell, app.js, and a UiPage controller.
  • Any backend (Node.js) — the tree is plain JSON; serve it from Express, Go, Python — no Java required.
  • Embed as a UI island — mount one tree into a <div> on any existing page.
  • Rendering modes — SSR, SPA, and partial updates with UiPatch.
  • Server-side rendering — render to HTML on the JVM, no JavaScript required.
  • The editor — the embeddable visual editor.
  • Shop demo — a full Postgres-backed CRUD app end to end.
  • How it compares — versus HTMX, Datastar, Inertia.js and Vaadin Flow.

Self-contained​

semantic-ui does not depend on the agents/ or workflow/ areas — drop it into any existing Spring Boot app as a dependency.

<dependency>
  <groupId>ai.mindconnect</groupId>
  <artifactId>mc-semantic-ui-core</artifactId>
  <version>0.0.1-SNAPSHOT</version>
</dependency>
